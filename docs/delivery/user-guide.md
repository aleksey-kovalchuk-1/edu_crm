# Работа с UniCRM

## Роли

| Роль | Основная работа |
| --- | --- |
| КАМ (`crm-user`) | ведёт назначенные вузы и вузы с пометкой «Видят все КАМ», взаимодействия и задачи; видит отчёты только в своей области доступа |
| Руководитель (`crm-supervisor`) | видит все вузы, назначает КАМ на вузы, включает «Видят все КАМ», настраивает процессы, справочники и шаблоны планов |
| Администратор платформы (`crm-admin`) | те же права, что у руководителя, плюс настройки организации |
| Суперадминистратор (`crm-superadmin`) | всё перечисленное, а также пользователи и роли, заявки на доступ и резервные копии; может передать права суперадминистратора администратору |
| Главный суперадминистратор | суперадминистратор, указанный в `PRIMARY_SUPERADMIN_USERNAME` (Ирина); единственный, кто может снять права суперадминистратора; его собственные права не снимаются |

Для точной матрицы действий используют Swagger UI и проверку серверных разрешений: видимость кнопки в браузере не заменяет разрешение API.

## Управление пользователями и доступом (суперадминистратор)

1. **Регистрация.** Человек регистрируется на странице входа (адрес только в домене `.ru`) и подтверждает адрес по письму. Суперадминистраторам приходит уведомление «Новая заявка на доступ», администратору — письмо.
2. **Выдать доступ:** «Настройки → Пользователи и роли → Заявки на доступ», выбрать КАМ, руководителя или администратора и нажать «Выдать доступ». Если человек ещё не задал пароль, ему уходит письмо «UniCRM: доступ выдан — задайте пароль» (ссылка действует 12 часов); повторно его можно отправить кнопкой «Отправить письмо для пароля».
3. **Изменить роль:** в таблице «Пользователи CRM» нажать «Изменить роль», выбрать роль и «Сохранить». «Удалить роль» (с подтверждением) закрывает доступ к CRM и возвращает человека в заявки.
4. **Права суперадминистратора:** у администратора — кнопка «Сделать суперадминистратором». Снять права («Снять права суперадминистратора») может только главный суперадминистратор; после снятия человек снова администратор.
5. **Видимость вуза:** руководитель или администратор на карточке вуза включает «Видят все КАМ»; иначе вуз видят только назначенные КАМ.

## Основной сценарий

1. После входа найти вуз по имени; если его нет, создать карточку в разрешённом разделе и назначить ответственного.
2. Создать взаимодействие с программой, ИТ-продуктом, ответственным и сроком. Смена этапа записывается в историю; комментарий сам по себе не является переходом.
3. В «Взаимодействиях» сузить реестр фильтрами «Вуз», «ИТ-программа», «ИТ-продукт» и «Статус»; ссылку на отфильтрованный реестр можно передать коллеге.
4. Создавать и выполнять задачи по взаимодействию. При загрузке справочников сначала просмотреть сопоставление колонок и ошибки, затем применить проверенные строки.
5. Открыть «Аналитику» для воронки, внедрений по месяцам и рейтинга; при отсутствии подтверждённых событий будет пустое состояние или явно обозначенный браузерный пример. PDF формируется только из серверных данных.

## Скачать результат в JSON

1. Открыть **«Отчёты»**. Выбрать период, один или несколько вузов (пустой выбор — все доступные), другие фильтры и колонки.
2. Сверить число найденных взаимодействий. Если период задан наоборот, сначала исправить его: кнопки скачивания будут недоступны.
3. Нажать **«JSON»** в блоке «Скачать». Браузер сохранит файл `interactions-report-YYYYMMDD.json`. Он содержит все подходящие записи, даже когда таблица показывает первые 200.
4. Открыть файл в редакторе UTF-8 или передать в согласованную систему. Метаданные `filters` и `columns` объясняют, как получены `rows`; `total` — число строк в файле. Экспорт сохраняется в журнале действий.

```json
{
  "schema_version": 1,
  "generated_at": "<момент UTC в ISO 8601>",
  "organization": "<название организации из CRM>",
  "filters": {"period_from": null, "period_to": null, "university_id": [], "it_direction_id": [], "it_product_id": [], "owner": [], "status_id": []},
  "columns": [{"key": "university", "label": "Учебное заведение"}],
  "total": 0,
  "rows": []
}
```

Пример показывает **форму**, а не статистику или действительный экспорт. Для автоматической обработки ориентироваться на `schema_version` и ключи колонок, а не на русские подписи. Если выбрать колонку «Последний комментарий» или «Ответственный», файл может содержать персональные данные; передавать его только по утверждённым правилам.
