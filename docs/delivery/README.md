## Область поставки

Исходный код React и FastAPI поставляется как текст без обфускации. Контейнеры собираются из него. Локальный запуск использует PostgreSQL и Keycloak. Данные LMS и сайта ИТ Школы по решению владельца от 29.09.2026 загружаются через «Загрузку справочников» (файлы выгрузок с предварительным просмотром и журналом, D-243); API-коннекторов к LMS и сайту нет, и сервис не обращается к ним по сети. Юридическое заключение о соответствии 149-ФЗ, 152-ФЗ и ГОСТ не входит в программную документацию: его должен дать профильный юрист/специалист по защите информации по фактическим данным и условиям эксплуатации.

## Приёмочная проверка комплекта

1. Запустить систему по [инструкции](linux-install.md), открыть Swagger UI и проверить ролевой вход.
2. В «Отчётах» выбрать период, вуз и колонки; сопоставить число строк предпросмотра и поля полного JSON. При более чем 200 строках предпросмотр показывает первые 200, а файл содержит все доступные строки.
3. Открыть файл как UTF-8 JSON и проверить `total`, `columns`, `filters` и `rows`. Повторить вход под КАМ с меньшей областью доступа: чужие вузы не должны появиться в файле.
4. Проверить «Аналитику» и PDF по правилам из [обработки данных](data-processing.md); демонстрационный вид в браузере не является подтверждённой статистикой.
5. Под суперадминистратором открыть «Настройки → Пользователи и роли»: выдать доступ, изменить роль (КАМ, руководитель, администратор), удалить роль, передать права суперадминистратора администратору; под другим суперадминистратором убедиться, что снять эти права нельзя (это может только главный суперадминистратор).
6. В «Взаимодействиях» отфильтровать реестр по вузу, ИТ-программе, ИТ-продукту и статусу; на карточке вуза переключить «Видят все КАМ» и проверить видимость под КАМ.
7. Импортировать [модель](unicrm-architecture.xml) в Archi и проверить отображение элементов и связей. Синтаксис XML и ссылки между элементами проверены автоматически; графическое размещение в конкретной версии Archi требует ручной проверки.
