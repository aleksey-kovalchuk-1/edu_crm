# Тезисы для презентации UniCRM

Этот текст можно перенести на 2–3 слайда. Формулировки описывают исходный код от 29.09.2026 (выпуск v1.0.0 и последующие изменения); перед выступлением нужно сверить фактический релиз на сайте.

## Слайд 1. Задача и решение

**Заголовок:** «UniCRM: единое рабочее место для взаимодействия с вузами».

- КАМ ведёт вуз, программу и задачи в связанных карточках; руководитель видит общий ход работы, администратор сопровождает платформу.
- Решение является отдельным сервисом: React в браузере, FastAPI с документированным HTTP API, PostgreSQL для данных, Keycloak для входа и ролей. Компоненты собираются в Docker-контейнеры и могут размещаться на Linux.
- Данные ограничиваются на сервере по роли и назначенным вузам. Открытый исходный код и миграции передаются заказчику.

**Подпись к схеме:** «Браузер → веб-сервер → API → база и вложения; вход через Keycloak; файлы заказчика проходят проверку перед импортом».

## Слайд 2. Проверяемые результаты

**Заголовок:** «От записи взаимодействия до проверяемого отчёта».

- Воронка считает уникальные вузы по реально зафиксированным переходам этапов. Программа считается внедрённой при первом переходе в «Обучение», месяцы берутся в выбранном часовом поясе.
- Отчёт по взаимодействиям фильтруется по периоду, вузам, направлению, продукту, ответственному и статусу. Результат скачивается в XLS, XLSX, PDF и **полный JSON**. JSON содержит версию схемы, фильтры, список колонок, число строк и данные; экспорт журналируется.
- Предпросмотр ограничен 200 строками для удобства интерфейса; файл содержит все строки в области доступа пользователя. Цифры и графики следует сверять с исходными взаимодействиями и историей статусов.

**Демо на питче:** войти как КАМ → выбрать вуз → показать переход этапа в истории → открыть аналитику → в «Отчётах» выбрать фильтр и скачать JSON → показать `filters`, `total` и `rows`. Повторить с другой ролью, чтобы показать границу доступа.

## Слайд 3. Границы и развитие

**Заголовок:** «Честная граница данных: LMS и сайт ждут контракт».

- Рабочие источники — файлы заказчика и ручной ввод. Данных LMS и сайта в CRM нет: контракты заказчика не получены. Подготовлена только предварительная граница интеграции (внутренний пример формата, ничего не сохраняет).
- Демонстрационный вид пустой аналитики помечен как пример и не попадает в PDF. Нули по старым данным не превращаются в подтверждённые сведения о студентах.
- Администрирование: суперадминистратор управляет ролями и может передать свои права администратору; снять их может только главный суперадминистратор. Видимость вуза для всех КАМ включается на карточке вуза.

**Не заявлять на слайдах без отдельного подтверждения:** «соответствует 152-ФЗ/ГОСТ», «получает данные из LMS автоматически», «все показатели подтверждены заказчиком», «прошёл нагрузочные испытания на инфраструктуре заказчика».
