# Аналитика взаимодействий — решение от 27.09.2026

## Цель и границы

Заменить содержимое страницы «Аналитика» четырьмя блоками: общие фильтры и PDF,
воронка пяти этапов, внедрения по месяцам, рейтинг пяти вузов. Страница и PDF используют
один серверный снимок показателей. Раздел «Настройки» и профиль не меняются в этой ветке;
изменения не публикуются без отдельного согласия заказчика.

## Данные и определения

- Источник — `launches` и история `status_changes` раздела «Взаимодействия», с вузами из
  `universities`. Данные `annual_metrics` прежней аналитики больше не используются.
- Пять этапов и их порядок берутся из `workflows.STAGE_GROUPS`, общего словаря для доски
  взаимодействий. Группа статуса определяется существующей `stage_group(position)`.
- Для воронки в периоде считаются уникальные вузы, у которых была записана смена статуса
  внутри периода. Максимальная достигнутая группа такого вуза даёт ему зачёт во всех
  предыдущих группах. Записи с комментарием или файлом без смены статуса не считаются
  переходом. Поэтому последовательность количеств не возрастает.
- Одна программа — одна запись `Launch`. Дата внедрения — первая записанная смена статуса
  из группы до «Обучения» в группу «Обучение». Начальное размещение записи в «Обучении» и
  повторные переходы не создают фиктивных внедрений. Это правило выбрал заказчик.
- Месячный график считает внедрения по календарным датам выбранного часового пояса,
  включая обе границы периода. Между месяцами с внедрениями нулевые месяцы сохраняются.
- Рейтинг показывает до пяти вузов по числу внедрённых программ за период, затем по
  сумме поля `Launch.students` у этих программ, затем по названию для стабильности.
  Если внедрений нет, рейтинг показывает состояние без данных.
- Существующие восемь демонстрационных взаимодействий показываются наравне с остальными:
  заказчик выбрал это явно. Они не получают выдуманных дат внедрения. В двух более поздних
  записях значение `students` равно 0, и текущая схема не отличает настоящий ноль от
  неизвестного числа; в интерфейсе нельзя утверждать, что это подтверждённый набор.
  При таком нуле рейтинг ставит звёздочку и показывает пояснение также в PDF.

## Фильтры и доступ

- Даты передаются как ISO `YYYY-MM-DD`; пользователю показываются как `DD.MM.YYYY`.
  По умолчанию — 1 января текущего года и текущий день в выбранном часовом поясе.
  Сервер и интерфейс отвергают начало позже конца с понятной ошибкой.
  Период ограничен 120 календарными месяцами с понятной ошибкой, чтобы выгрузка
  PDF и график не перегружали приложение.
- Пустой набор вузов означает «Все вузы». Непустой набор может содержать несколько ID.
  Сервер сначала применяет `university_scope`, а затем выбранные ID. Недоступный или
  неизвестный ID отклоняется без раскрытия чужих данных. Те же правила применяются к PDF.
- Часовой пояс берётся из профиля пользователя; если поле пусто, используется
  `Intl.DateTimeFormat().resolvedOptions().timeZone` с видимой пометкой. Имя зоны
  передаётся серверу, проверяется через `zoneinfo`; JSON и PDF получают одинаковые границы
  и месяцы.

## Контракт и вывод

- `GET /api/v1/analytics/interactions` возвращает выбранный период, названия выбранных
  вузов, временную зону, пять значений воронки, все месяцы периода и до пяти строк рейтинга.
- `GET /api/v1/analytics/interactions.pdf` применяет те же параметры и тот же расчётный
  метод. В документе есть три графика, период, список вузов и дата генерации. В шрифтах
  DejaVu, встроенных ReportLab, поддерживается кириллица. Имя файла содержит период.
- При отсутствии событий за период блок графика показывает «Нет данных за выбранный период».
  Для месяцев это состояние применяется, когда не было ни одного подтверждённого внедрения;
  при наличии хотя бы одного внедрения остальные месяцы отображаются с нулём.

## Проверка

Тесты покрывают монотонность воронки и уникальность вузов, переход в «Обучение»,
месячные границы и нулевые месяцы, рейтинг и сортировку, неверный период, серверную
область доступа и одинаковые значения в JSON и PDF. Проверяется визуальная читаемость PDF.
