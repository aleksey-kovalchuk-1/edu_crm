# Файлы заказчика в «Загрузке справочников»

Решение владельца от 29.09.2026 — D-247. Заказчик передал три файла: `Данные оплат.json` и книгу
`RTK_IT_School_CRM_20.xlsx` (вторая книга, `…_Universities_Pilot.xlsx`, совпадает с ней по всем значениям ячеек).
«Загрузка справочников» (`/imports`) выбирает загрузчик по содержимому файла:

- JSON-массив — загрузчик заявок;
- `.xlsx` с листами «Вузы» и «Продукты РТК» — загрузчик книги заказчика;
- любая другая таблица Excel — прежняя загрузка реестра договоров по столбцам первого листа, без изменений.

Порядок везде один: загрузка → состав файла → проверка без записи → применение. Загружать могут «Руководитель» и
«Администратор»; КАМ — нет. Отдельного раздела заявок в интерфейсе нет, «Заявки на курсы» не восстанавливаются.

## Заявки (JSON)

Проверенная структура файла: массив из 6 элементов, один — `null`; у остальных поля «Номер заявки» (строка),
«Курс» (строка), «Фамилия», «Имя», «Отчество», «Телефон», «Email» (строки), «Номер потока» (целое).

- Читаются **только** «Номер заявки», «Курс», «Номер потока». ФИО, телефон и почта отбрасываются при чтении файла,
  до сохранения, и не попадают ни в базу, ни в запись загрузки, ни в отчёт.
- Заявка ищется по номеру: найдена — обновляются курс и поток, иначе создаётся. Дублей не бывает; номер, повторённый
  в файле, берётся из последней записи, более ранние отмечаются как пропущенные.
- `null` и записи, не являющиеся объектом, пропускаются; записи без номера, курса или потока, с неверным типом или
  слишком длинным значением — ошибка строки. Всё перечислено в отчёте.
- Статус оплаты не выводится из названия файла и не меняется: у всех заявок остаётся «Не подтверждено данными»
  (`unconfirmed_by_data`, закреплено ограничением базы).
- Заявка хранится без слушателя (`course_applications.learner_id` пуст).

## Книга заказчика: какие листы что обновляют

Листы определяются по названию, «Сводка» не считается листом данных. Строка заголовков ищется в первых 10 строках
листа по столбцу-идентификатору.

| Лист | Сущность CRM | Что происходит |
|---|---|---|
| Вузы | Учебное заведение | **Только существующие вузы.** Сопоставление по `university_id`, при первой загрузке — по точному полному или краткому названию среди действующих вузов. Обновляются краткое название, регион, город, сайт; название вуза в CRM не меняется. Вуз, которого нет в каталоге, **не создаётся**: он перечисляется при проверке, его строка пропускается. |
| Направления | ИТ-направление | По `direction_id` (при первой загрузке — по названию): обновляются название и описание, новое направление создаётся. |
| Продукты РТК | ИТ-продукт | По `product_id` (при первой загрузке — по названию у вендора «ПАО «Ростелеком»»): обновляются название и описание, новый продукт создаётся с вендором и компанией «ПАО «Ростелеком»». |
| Программы | нет | Не загружается: программа вуза в CRM — только текст во взаимодействии. |
| Договоры | Договор | Не загружается: шаблон не заполнен (нет номеров и дат), а договор CRM связан с одним продуктом. |
| Продукты договора | нет | Не загружается: шаблон не заполнен, связь договоров с продуктами не утверждена. |
| Ответственные | Назначение КАМ | Не загружается: шаблон не заполнен (нет сотрудников). |
| Допсоглашения, Источники | нет | Не загружаются: в CRM нет такой сущности. |
| Сводка, Справочники, Инструкция | — | Служебные листы, не загружаются. |
| Любой другой лист | — | «Лист не распознан; не загружается». |

Каждый лист показывается на шаге «Состав файла» и в истории загрузок со статусом и причиной. Неподдерживаемые листы
не читаются и никогда не записываются в другие сущности.

Идентификаторы книги хранятся в `external_id` у вузов, ИТ-направлений и ИТ-продуктов (правило 9 книги: не менять
их после загрузки), поэтому повторная загрузка той же книги с новыми данными обновляет те же записи.
