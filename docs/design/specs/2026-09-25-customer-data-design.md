# Данные заказчика: компании, слушатели, заявки

## Цель и границы

UniCRM хранит поставщиков, их продукты и ответственных контактов; анкеты слушателей; заявки на курсы и потоки. Действующие договоры, взаимодействия и отчёты продолжают работать с `ITProduct.vendor` и существующими ID. Источник `/Users/alex/Downloads/Данные оплат.json` содержит пять заявок и один `null`, но не содержит сведений о факте оплаты. Исходные персональные данные не загружаются в рабочую БД при разработке.

Первая и вторая таблицы доступны только как перечни столбцов в ТЗ; реализация и тесты используют синтетические строки. После получения файлов сопоставление заголовков и форматов проверяется на их структуре без записи в БД. Вторая таблица трактуется как анкета слушателя: текущая модель `Launch.students` хранит лишь число и не описывает людей.

## Компания и каталог

`VendorCompany` имеет уникальное нормализованное название и признак активности. `ITProduct.company_id` nullable, чтобы существующие продукты и ссылки на них сохранились. Миграция создаёт компании для уникальных значений `vendor`, связывает соответствующие продукты, оставляет `vendor` как действующий текстовый контракт. Компания может иметь несколько продуктов. `VendorContact` принадлежит компании, имеет ФИО, телефон, email, список предпочтительных способов связи и признак активности. Связь контакта и продукта — многие ко многим; API отвергает продукт другой компании. «Чат в ТГ» — способ связи, не адрес.

Списки компаний и контактов доступны всем действующим ролям; создание, редактирование и деактивация — руководителю и администратору, как для ИТ-продуктов. Поиск и фильтр продукта выполняются на сервере. В карточке продукта видны контакты его компании, отвечающие за продукт.

## Анкета слушателя и защита данных

`Learner` хранит ФИО и необязательные поля из ТЗ. Документные номера, СНИЛС, телефон и индекс — строки. Паспортные поля и СНИЛС шифруются отдельным ключом `LEARNER_DATA_ENCRYPTION_KEY` из окружения; отсутствие ключа не мешает запуску старых функций, но закрывает запись и чтение полной анкеты. Ключ не возвращается через API и не пишется в журнал. Общий список содержит только имя и контакты; полная карточка, создание и правка доступны только руководителю и администратору через серверную проверку. Журнал фиксирует тип операции и ID без значений анкеты.

Повторный импорт сопоставляет человека по нормализованному email или телефону лишь при единственном непротиворечивом результате. ФИО используется для показа кандидатов, но не для автоматического объединения. Пустая ячейка не очищает заполненное поле. Неоднозначности сообщаются до применения.

## Заявки и импорт

`CourseApplication` имеет уникальный внешний номер, курс, номер потока, ссылку на слушателя и статус `unconfirmed_by_data` («Не подтверждено данными»). Импорт JSON пропускает `null` с построчным предупреждением, проверяет обязательные поля и дубли, создаёт или обновляет заявку идемпотентно. Оплату и финансовые показатели этот источник не меняет.

Для каждого вида импорта сервер принимает файл в память с ограничением размера, сразу выполняет предварительную проверку без записи и выдаёт построчный отчёт. Применение — отдельный запрос с повторной проверкой входа в одной транзакции. Исходный файл и строки анкеты не сохраняются в репозитории, импортной истории или аудите. Отчёты об ошибках исключают паспорт и СНИЛС.

## Интерфейс, совместимость и проверка

React показывает списки и карточки компаний/контактов, слушателей и заявок, поиск и фильтры. Полная анкета запрашивается отдельным API вызовом только для разрешённых ролей. Импорт даёт просмотр результатов перед применением. Новые таблицы и nullable FK добавляются последовательными Alembic миграциями. Проверяются правила доступа, шифрование, отсутствие утечек, идемпотентность, миграция и действующие сценарии продукта; затем backend и frontend тесты, типы, lint и сборка.

Существующий скрипт `db-backup.sh` создаёт незашифрованный `pg_dump` вне репозитория. До загрузки реальных анкет в рабочую БД нужно внедрить защищённое хранение копий, ограничить доступ к ним и проверить восстановление вместе с управлением ключом.
