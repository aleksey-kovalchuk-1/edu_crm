# Процессы взаимодействия, статусы, комментарии и файлы

Статус: проект для задач T-040–T-043. Решения — D-149–D-154 в `docs/decisions.md`.

## Что требует спецификация

- Визуализировать путь взаимодействия с вузом; переключать статусы; настраивать названия статусов; оставлять комментарий при смене статуса.
- Прикреплять к статусам файлы png, jpeg, pdf, zip, gzip, rar, doc, docx, xls, xlsx.
- Создавать и изменять процессы; базовый процесс описан 14 пунктами.
- Интерфейс не перезагружает страницу; смена статуса и комментарий — не дольше 1 секунды.

## Модель

| Таблица | Назначение | Поля |
|---|---|---|
| `workflow_templates` | Процесс | `id`, `name`, `description`, `is_default`, `is_active`, `created_at` |
| `workflow_statuses` | Статусы процесса | `id`, `template_id`, `name`, `position`, `is_final`, `is_active` |
| `launches` (есть) | Взаимодействие: вуз + программа + продукт | новые `workflow_template_id`, `status_id`; поле `stage` сохраняется как номер позиции текущего статуса для совместимости |
| `status_changes` | История смен статуса | `id`, `launch_id`, `from_status_id`, `to_status_id`, `comment`, `user_id`, `created_at` |
| `attachments` | Файлы к смене статуса | `id`, `status_change_id`, `launch_id`, `filename`, `content_type`, `size_bytes`, `sha256`, `storage_key`, `uploaded_by_user_id`, `created_at` |

- **Статус хранится ссылкой на запись**, а не номером: переименование или перестановка статуса не меняет историю.
- **Базовый процесс «Типовое взаимодействие с вузом»** создаётся миграцией из 13 статусов текущего шаблона. Они покрывают пункты 1–13 спецификации; пункт 5 «исправление документов» соответствует статусу «Согласование документов». Пункт 14 «контроль исполнения каждого этапа» — это не отдельный статус, а функция системы: сроки, просрочка, история и отчёты.
- **Существующие данные:** каждому взаимодействию назначаются базовый процесс и статус по текущему `stage`; строки `stage_events` переносятся в `status_changes` без автора и комментария. Таблица `stage_events` сохраняется до отдельного решения об удалении.

## Правила смены статуса

- Разрешён переход в любой активный статус того же процесса, в том числе назад («возврат на доработку»). Ограничение допустимых переходов по регламенту заказчика откладывается до получения регламента.
- Комментарий необязателен, до 2000 символов.
- Смена статуса, комментарий и файлы сохраняются одной транзакцией вместе с событием журнала действий.
- Менеджер меняет статусы только во взаимодействиях своих вузов (D-141).

## Настройка процессов

- Руководитель и администратор создают процессы, добавляют, переименовывают, переставляют и деактивируют статусы.
- Деактивированный статус нельзя выбрать для новой смены, но он остаётся в истории; статус, в котором находятся взаимодействия, нельзя деактивировать.
- У процесса должен быть хотя бы один активный статус; базовый процесс можно изменять, но не деактивировать.

## Файлы

- **Проверка типа.** Допустимые форматы определяются по сигнатуре содержимого и расширению:
  - PNG — `89 50 4E 47`;
  - JPEG — `FF D8 FF`;
  - PDF — `%PDF`;
  - gzip — `1F 8B`;
  - RAR — `Rar!`;
  - DOC и XLS — формат OLE, `D0 CF 11 E0`;
  - ZIP, DOCX и XLSX — `PK\x03\x04`, причём для DOCX и XLSX дополнительно проверяется содержимое архива.
- **Ограничения.** До 20 МБ на файл и до 5 файлов на одну смену статуса. Архивы не распаковываются и не исполняются.
- **Хранение.** Файлы лежат в томе Docker `attachments_data` под случайным ключом, без исходного имени в пути (D-110). В базе хранятся метаданные и SHA-256.
- **Скачивание.** `GET /api/v1/attachments/{id}` с проверкой области видимости, заголовками `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`.

## API

| Метод и путь | Роли | Описание |
|---|---|---|
| `GET /api/v1/workflows` | все | Процессы с активными статусами |
| `POST /api/v1/workflows` | руководитель, администратор | Создать процесс со статусами |
| `PATCH /api/v1/workflows/{id}` | руководитель, администратор | Название, описание, активность |
| `POST /api/v1/workflows/{id}/statuses` | руководитель, администратор | Добавить статус |
| `PATCH /api/v1/workflow-statuses/{id}` | руководитель, администратор | Переименовать, признак финального, активность |
| `PUT /api/v1/workflows/{id}/status-order` | руководитель, администратор | Новый порядок статусов |
| `POST /api/v1/launches/{id}/status-changes` | все (в области видимости) | `multipart/form-data`: `status_id`, `comment`, `files[]` |
| `GET /api/v1/launches/{id}/status-changes` | все (в области видимости) | История с комментариями, авторами и файлами |
| `GET /api/v1/attachments/{id}` | все (в области видимости) | Скачать файл |
