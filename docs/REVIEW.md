# Руководство для ревьюера

UniCRM — MVP сервиса для работы с учебными заведениями: вузы, взаимодействия с этапами, задачи, отчёты, аналитика,
роли и загрузка файлов. Ниже — как запустить его у себя за 10 минут и что проверить. Все данные в репозитории
вымышленные.

## Что намеренно не лежит в репозитории

Репозиторий публичный, поэтому в нём нет и не будет: рабочих данных (базы, резервных копий, томов Docker), секретов
(`deploy/local/`, ключей, учётных данных туннеля) и настоящих файлов заказчика — в них персональные данные. Для
проверки есть демо-данные (`backend/app/seed.py`) и синтетические образцы в [`docs/samples/`](samples/).

## Запуск (Docker)

Нужны Docker Engine, Docker Compose v2 и `openssl`.

```bash
cp .env.example .env
scripts/generate-dev-secrets.sh      # случайные локальные пароли в deploy/local/ (не попадают в git)
docker compose up --build -d          # первый запуск Keycloak — около минуты
```

- CRM: http://localhost:8080 — вход через Keycloak
- Swagger: http://localhost:8080/api/docs

Учётные записи (пароли — в `deploy/local/keycloak.env`):

| Логин | Роль |
|---|---|
| `irina_super_admin` | руководитель и главный суперадминистратор |
| `admin_1`, `admin_2` | администратор |
| `manager_1`, `manager_2` | КАМ |

## Что попробовать

1. **Роли и видимость.** КАМ видит только назначенные ему вузы и вузы с признаком «Видят все КАМ»; руководитель
   и администратор — все. Пользователями и ролями управляет суперадминистратор («Настройки → Пользователи и роли»).
2. **Взаимодействия.** Реестр с фильтрами, карточка программы, смена этапа с историей, задачи.
3. **Отчёты и аналитика.** Воронка, внедрения по месяцам, рейтинг; выгрузка отчёта в XLS, XLSX, PDF и JSON.
4. **Загрузка файлов заказчика** — войдите как `irina_super_admin` → «Загрузка справочников»:
   - [`samples/rtk-workbook-sample.xlsx`](samples/rtk-workbook-sample.xlsx) — книга в структуре заказчика. На шаге
     «Состав файла» видны все 12 листов со статусом. «Проверить» покажет: 2 вуза будут обновлены, «Приморский
     университет программной инженерии» не найден и будет пропущен (вузы не создаются), будут созданы 2
     ИТ-направления и 2 ИТ-продукта. Повторная загрузка того же файла ничего не дублирует.
   - [`samples/applications-sample.json`](samples/applications-sample.json) — заявки: 3 будут созданы, пустая запись
     `null` пропущена. Из файла берутся только номер заявки, курс и поток; ФИО, телефоны и почта не сохраняются.
   - Под `admin_1` те же файлы получают отказ: файлы заказчика загружает только руководитель. Обычный реестр
     договоров по столбцам — [`samples/catalog-import-sample.xlsx`](samples/catalog-import-sample.xlsx).
5. **Граница интеграции LMS и сайта.** `GET /api/v1/integrations/contracts` в Swagger — предварительный внутренний
   формат, не контракт заказчика; заглушки `POST` ничего не сохраняют.

## Тесты

Тесты сервера работают на PostgreSQL (у каждого теста своя база):

```bash
docker compose up -d db
cd backend && ../.venv/bin/python -m pytest -q     # зависимости: backend/requirements-dev.txt
cd ../frontend && npm ci && npx vitest run && npx tsc -b && npx eslint .
```

Синтетические образцы пересоздаются командой `python3 scripts/generate-review-samples.py`;
`backend/tests/test_review_samples.py` проверяет, что они повторяют структуру файлов заказчика, содержат только
вымышленные контакты и дают на демо-данных результаты, описанные выше.
