# Настройки → Уведомления

Срез 3 из 5 запроса «Настройки» от 27.09.2026. Согласовано с владельцем 27.09.2026: начальные состояния — «включены только личные»; пауза с выбором длительности; одно действие = одно уведомление; договоры из импорта не создают «Подписали договор».

## События, получатели, источники

Автор действия уведомление о своём действии не получает. Получатель должен видеть запись в момент создания уведомления (`university_in_scope` / политика задач).

**Одно действие — одно уведомление.** Для одного `StatusChange` получатель получает одно уведомление первого включённого у него типа из `launch_completed` → `launch_stage_changed` → `launch_comment_or_file` (подходящего по фактам: финальный статус / смена статуса / комментарий или файл). Прочие события одного действия с одинаковым получателем и сущностью тоже не дублируются.

Ссылки: вуз → `/universities/{id}`, взаимодействие → `/interactions/{id}`, задача → `/tasks/{id}`, договор → страница вуза. Пункт меню «Договоры» не возвращается.

## Механизм

- Перехват изменений: слушатели сессии SQLAlchemy (`before_flush` запоминает изменения атрибутов и удаляемые строки, `after_flush` — вставленные), в `before_commit` накопленные изменения превращаются в уведомления в той же транзакции. Автор — `session.info['actor_user_id']`, выставляется при аутентификации. Импорт выставляет `session.info['notification_source'] = 'import'` — договоры из него не создают `contract_signed`.
- Создание уведомления: пропустить, если получатель — автор, неактивен, событие у него выключено, уведомления приостановлены (`paused_until > now`), или он не видит запись.
- Хранение (миграция `0027`): `notifications` (получатель, тип, заголовок, текст, тип и id ссылки, `university_id`, автор, `dedupe_key`, `created_at`, `read_at`; уникальность `(user_id, dedupe_key)` для непустого ключа); `notification_preferences` (только изменённые пользователем флажки); `users.notifications_paused_until` (NULL — не на паузе; `infinity` — до выключения).
- Показ: список и счётчик отфильтрованы по текущей видимости — потерявший доступ к вузу/задаче их уведомлений не видит.

## Планировщик

Сервис Compose `notifier` (тот же образ, `python -m app.notification_scheduler`, цикл каждые 15 минут; `--once` для одного прогона). Для каждого активного пользователя «сегодня» считается в его часовом поясе; события «сегодня/просрочено» создаются при первом прогоне после 08:00 по его времени. `dedupe_key`: `task_due_today:{task_id}:{deadline}`, `task_overdue:{task_id}:{deadline}`, `license_expires_{30|7}:{contract_id}:{valid_until}` — повторные прогоны ничего не добавляют, перенос срока снова уведомляет. Задачи в статусах `completed`/`cancelled` и архивные не участвуют. Сервис добавляется в `compose.yaml` и `compose.public.yaml`; в рабочей системе запускается только при выпуске с разрешения владельца.

## Пауза

`PUT /notifications/pause` с `duration` ∈ `1h`, `tomorrow` (до 08:00 следующего дня по времени пользователя), `1w`, `forever`, `off`. Пока пауза действует, уведомления не создаются и не копятся; флажки не меняются; по истечении срока пауза снимается сама.

## API и интерфейс

- `GET /notifications?unread=true&limit=50`, `GET /notifications/unread-count`, `POST /notifications/{id}/read`, `POST /notifications/read-all`, `GET /notifications/preferences` (группы, 20 пунктов с `enabled`, `paused_until`), `PUT /notifications/preferences` (`{event_type: bool}`), `PUT /notifications/pause`. Всё — только для себя, любая роль.
- Колокольчик справа в шапке каждой страницы: без непрочитанных — нейтральный; с непрочитанными — выделен, со счётчиком; счётчик обновляется раз в 60 секунд; по нажатию — список со ссылками, «Отметить все прочитанными», прочтение по нажатию на пункт.
- «Настройки → Уведомления»: 4 группы флажков, переключатель паузы с выбором длительности и показом, до какого времени действует пауза, кнопка «Сохранить», сообщение об успехе.

## Проверка

Бэкенд: каждое из 20 событий — ровно нужные получатели; нет уведомления автору; выключенное событие и пауза ничего не создают; пауза заканчивается сама; одно действие смены статуса с комментарием и файлом — одно уведомление; импорт договора — без `contract_signed`; потеря доступа скрывает уведомление; «сегодня» по часовому поясу (Владивосток и Москва в один момент); повторный прогон планировщика ничего не добавляет; перенос срока — новое уведомление. Фронтенд: два состояния колокольчика, список со ссылками, прочтение, страница настроек.

## Пробелы данных

Нет. Ограничения: комментарий или файл к взаимодействию сейчас добавляется только вместе со сменой статуса; «подписание договора» — это создание записи договора вручную.
