## API

- `GET /api/v1/organization` — все поля, любая роль CRM.
- `PUT /api/v1/organization` — все поля целиком, только `crm-admin` или `crm-superadmin`; `422` с `details[].field` и русскими сообщениями; событие журнала `organization.update` с названиями изменённых полей.
- `GET /api/v1/organization/brand` — **публичный**, только `{"name"}` (экран входа показывается до входа); вносится в список публичных эндпоинтов `tests/test_rbac.py`.

## Интерфейс

«Настройки → Организация»: администратор видит форму всех полей с одной кнопкой «Сохранить», ошибками у полей и сообщением «Изменения сохранены»; остальные роли — те же сведения только для чтения. Панели адресов отправителей (срез 1) остаются ниже для руководителя и администратора.

## Где используется название

Название читается из таблицы в момент использования, поэтому правка действует сразу.

- Боковое меню и экран входа: под «UniCRM» второй строкой — название организации (из `/organization/brand`; при ошибке запроса строка не показывается).
- Выгрузки отчётов: первая строка листа xlsx/xls и строка над заголовком PDF — название организации; графики (PDF и PNG) — строка над заголовком.
- Письма CRM (подтверждение адреса отправителя, тестовое письмо): имя отправителя = название организации, если пользователь не выбрал свой адрес; тело письма заканчивается строкой с названием. `send_email` получает необязательный `from_name`; HTTP-провайдер получает его полем `from_name` (формат провайдера по-прежнему предполагаемый, D-210).

## Проверка

Бэкенд: чтение всеми ролями; правка администратором и `403` для остальных; каждая проверка поля (включая неверную контрольную цифру ОГРН и будущую дату); публичный `brand` отдаёт только название; значения после миграции; название в сгенерированных xlsx и PDF и в графике; имя отправителя и подпись в письмах. Фронтенд: правка администратором с ошибками и успехом; просмотр без формы для менеджера; название в меню и на экране входа.
