# Сопроводительная документация и JSON-отчёт — план

Основание: `docs/specification.md`, раздел «Requirements for the solution», и запрос владельца от 28.09.2026. Работа ведётся от опубликованного `a42dc0c`, отдельно от ветки настроек.

## Границы

- «Результирующий JSON-файл» — скачиваемый полный отчёт по взаимодействиям, полученный тем же серверным запросом, что XLS/XLSX/PDF. Пользователь выбирает те же фильтры и колонки. Предпросмотр остаётся ограничен 200 строками.
- Экспорт использует действующую серверную область доступа к вузам и журналирует операцию. В JSON не попадают анкеты слушателей, токены, секреты и демонстрационные графики.
- Сопроводительный комплект описывает реализованное состояние и явно отделяет недоступные API LMS/сайта, правовую оценку и непроверенные показатели производительности от работающих функций.

## Шаги

1. Добавить серверные тесты: полный JSON при >200 строках, фильтры и колонки, русские символы, отсутствие доступа к чужим вузам, заголовок скачивания и запись в журнал. Проверить ожидаемое падение до реализации.
2. Добавить `json` в маршрут экспорта с машиночитаемой схемой, метаданными периода/фильтров и полным списком строк. Сохранить существующий контракт XLS/XLSX/PDF. Прокомментировать нетривиальную границу `preview`/`export` и проверку прав.
3. Добавить тест кнопки и её URL в React; затем кнопку JSON в «Отчётах». Проверить, что ошибочный период блокирует и её.
4. Подготовить `docs/delivery/`: индекс, обработка данных и ограничения, архитектура, состав компонентов и библиотек, установка и проверка на Linux, инструкция пользователя/администратора, тезисы для презентации. Не заявлять формальную сертификацию или готовую интеграцию с недоступными API.
5. Дополнить Swagger описание JSON-экспорта, обновить корневой README, проверить ссылки и примеры. Если получится валидировать ArchiMate Exchange XML — приложить модель для импорта в Archi; иначе явно отметить необходимость импортной проверки.
6. Запустить полный фронтенд-набор, lint и build; серверный набор только на выделенной тестовой PostgreSQL. Проверить diff и оставить результат в отдельной ветке без публикации.
