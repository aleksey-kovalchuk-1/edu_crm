# Настройки → Уведомления — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Уведомления в приложении по 20 типам событий с персональными настройками, паузой, колокольчиком и планировщиком событий по датам.

**Architecture:** `app/notifications.py` — каталог типов (ключ, группа, подпись, умолчание), создание уведомления с проверками (автор, активность, флажок, пауза, видимость, дедупликация); `app/notification_events.py` — слушатели сессии, превращающие изменения моделей в события при коммите; `app/notification_scheduler.py` — события по датам; `app/notification_routes.py` — API. Фронтенд: `api/notifications.ts`, `NotificationBell` в шапке, страница настроек.

**Tech Stack:** SQLAlchemy session events, Alembic, FastAPI, zoneinfo; React, TanStack Query, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-27-notifications-design.md`

## Global Constraints

- Ветка `ai/profile-senders`; миграция `revision='0027'`, `down_revision='0026'`.
- Ключи типов и умолчания — ровно по таблице спецификации.
- Тесты — изолированная БД `127.0.0.1:55432`; `.venv/bin/python -m pytest`.
- Сервис `notifier` не запускать против рабочей системы; не пушить, не выпускать.
- Коммиты с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Массовые операции над задачами (bulk members/deadline/status) — по одному уведомлению на задачу и получателя, без дублей внутри одной транзакции.
- Откат транзакции после ошибки — уведомления не остаются (создаются в той же транзакции).
- Удалённый или деактивированный пользователь — не получает уведомлений; его старые уведомления не ломают список.
- Пользователь без часового пояса или с неизвестным поясом — используется `Europe/Moscow`.
- Счётчик непрочитанных совпадает со списком (оба фильтруются по видимости).
