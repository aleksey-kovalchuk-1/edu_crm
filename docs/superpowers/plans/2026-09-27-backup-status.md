# Настройки → Резервное копирование: статус

## Цель

Показать суперадминистратору последние полные пары зашифрованных копий базы и вложений, которые уже создают серверные скрипты. Архивы и ключ восстановления остаются на сервере вне доступа API.

## Шаги

1. Зафиксировать безопасный формат метаданных: время, тип копии, размеры двух файлов и отметка, проходила ли пара проверку расшифровки. Пути, имена файлов, ключи и содержимое не передавать.
2. Тестами проверить запись метаданных только после появления обоих непустых файлов, атомарное обновление и ограничение истории; подключить запись к ежедневному и выпускному сценариям.
3. Добавить серверный API чтения метаданных только для `crm-superadmin`; проверить запрет другим ролям и честное состояние при отсутствии файла/ошибке чтения.
4. Заменить заглушку страницы статусом и историей, показывать отсутствие настроенного источника и смысл отметки проверки. Проверить сборку и тесты.
5. В рабочем окружении дать API только чтение каталога с очищенными метаданными, не монтируя каталог архивов и не передавая ключ восстановления. Проверить доступ и отображение после публикации.

Ручной запуск отдельным безопасным серверным заданием зависит от выбора владельца; данная часть работает без запуска копирования из веб-процесса.
