# API карточки организации

Спецификация: `docs/superpowers/specs/2026-09-27-organization-settings-design.md`; решение D-227.

Одна карточка (`organization_profile`, строка `id = 1`), заполненная миграцией `0026` данными владельца.

## Чтение

`GET /api/v1/organization` — любая роль CRM:
`{"name", "legal_name", "ogrn", "registration_date", "legal_address", "postal_address", "contact_address", "phone", "phone_display", "email", "updated_at"}`. `phone` хранится нормализованным (`+74951966205`), `phone_display` — для показа (`+7 (495) 196-62-05`).

## Правка

`PUT /api/v1/organization` — только `crm-admin` или `crm-superadmin`, все поля кроме `phone_display` и `updated_at` целиком. Неизвестные поля — `422`.

| Поле | Проверка | Сообщение |
| --- | --- | --- |
| `name` | 1–200 символов | стандартное |
| `legal_name`, `legal_address`, `postal_address`, `contact_address` | 1–500 символов | стандартное |
| `ogrn` | 13 цифр, контрольная цифра = (первые 12 mod 11) mod 10 | «ОГРН — 13 цифр с верной контрольной цифрой» |
| `registration_date` | не позже сегодняшней даты | «Дата регистрации не может быть в будущем» |
| `phone` | российский номер (`8…`, `7…`, `+7…`) | «Телефон в формате +7 (XXX) XXX-XX-XX» |
| `email` | корректный адрес | стандартное |

Событие журнала `organization.update` содержит только названия изменённых полей.

## Название для экрана входа (без сессии)

`GET /api/v1/organization/brand` → `{"name"}`. Публичный: экран входа показывает название до входа. Других полей не отдаёт.

## Где используется название

Боковое меню и экран входа (второй строкой под «UniCRM»), первая строка xlsx/xls-выгрузки отчёта и строка над заголовком PDF, строка над заголовком графиков (PNG и PDF), имя отправителя и последняя строка писем CRM (подтверждение адреса отправителя, тестовое письмо — если пользователь не выбрал свой адрес). Название читается в момент использования. `send_email` принимает `from_name`; HTTP-провайдер получает поле `from_name` (формат предполагаемый, D-210).
