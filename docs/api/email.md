# API адресов отправителей писем

Спецификация: `docs/superpowers/specs/2026-09-27-profile-and-sender-addresses-design.md`, раздел 2; решения D-210, D-212, D-225, D-226.

Адрес пригоден для отправки, только если он активен (`is_active`), подтверждён (`status = "active"`) и общий (`is_shared`) или принадлежит пользователю. Это проверяется свежим чтением строки непосредственно перед каждой отправкой (включая тестовое письмо) и при выборе в профиле; при нарушении — `409 CONFLICT` «Выбранный адрес отправителя недоступен — выберите другой в профиле», подмены на системный адрес нет.

Представление адреса: `{"id", "email_address", "display_name", "is_active", "status", "is_shared", "rejection_reason", "usable"}`; `status` ∈ `pending_approval`, `awaiting_confirmation`, `active`, `rejected`.

## Для всех ролей

- `GET /api/v1/email-senders` — активные подтверждённые общие адреса и все собственные адреса вызывающего.
- `POST /api/v1/email-senders/requests` — `{"email_address", "display_name"}` → `201`, личная заявка в `pending_approval`. Одна открытая заявка на пользователя (`409`); адрес, занятый другой строкой, — `422` по `email_address`. Отклонённый, отозванный или деактивированный адрес можно запросить снова (строка переиспользуется).
- `DELETE /api/v1/email-senders/requests/{id}` — отозвать свою открытую заявку → `204`; ссылка подтверждения перестаёт действовать.
- `POST /api/v1/email-senders/test` — тестовое письмо на свой адрес (не чаще раза в минуту, D-212).

## Для `crm-supervisor` и `crm-admin`

- `GET /api/v1/email-senders/queue` — адреса в `pending_approval` и `awaiting_confirmation` с `requested_by`, `requested_at`.
- `POST /api/v1/email-senders/{id}/approve` → `{"delivered", "message"}`; строка переходит в `awaiting_confirmation`, на адрес уходит ссылка. Одобрить собственную заявку нельзя (`403`).
- `POST /api/v1/email-senders/{id}/reject` — `{"reason"}` (до 500 символов) → `204`.
- `POST /api/v1/email-senders/{id}/resend` → `{"delivered", "message"}`; не чаще раза в 60 секунд (`429`); новая ссылка аннулирует прежнюю.
- `POST /api/v1/email-senders` — общий адрес → `201`, сразу `awaiting_confirmation` и письмо со ссылкой. Ранее подтверждённый деактивированный общий адрес восстанавливается без повторного подтверждения.
- `DELETE /api/v1/email-senders/{id}` — деактивировать → `204`; выбор пользователей сохраняется, но отправка с адреса отклоняется; ссылка подтверждения перестаёт действовать.

## Подтверждение (без сессии)

`POST /api/v1/email-senders/confirm` — `{"token"}` → `{"email_address"}`. Токен одноразовый, действует 48 часов, в базе хранится только SHA-256. Просроченный, повторный, неверный токен или адрес, деактивированный/отозванный после отправки ссылки, — `409` «Ссылка недействительна или устарела». Личный адрес после подтверждения становится выбранным у владельца. Ссылка в письме ведёт на страницу `/confirm-sender`, где подтверждение требует нажатия кнопки (`GET` ничего не подтверждает). nginx ограничивает путь по адресу клиента (20 запросов в минуту).

## Отправка писем

`backend/app/email.py`: без `EMAIL_PROVIDER_URL` письмо только записывается в журнал API, и ответы одобрения, повторной отправки и тестового письма прямо сообщают об этом (`delivered: false`). Формат запроса к провайдеру — предполагаемый (D-210).
