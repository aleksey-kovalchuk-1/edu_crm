# API документов (PDF/DOCX, T-093/T-094)

Модель, состояния и карантин — `docs/design/file-ingestion-plan.md` §3.3/§3.4/§5.3; решения D-155, D-158, D-159, D-160 в `docs/decisions.md`. Изменяющие запросы требуют `X-CSRF-Token`. Ошибки — `{code, message, details}`.

Документ — версионируемая запись, привязанная к вузу, взаимодействию или договору (`entity_type`: `university` | `launch` | `contract`, `entity_id`). Это отдельная модель от вложений к сменам статуса (`docs/api/workflows.md`) — там один файл на одно событие истории без версий, здесь — версионируемая библиотека документов.

## Состояния версии

`uploaded → quarantined → validated → linked`, либо `→ rejected` на любом из первых двух переходов (проверка формата/подписи/размера или антивирус). `validated`→`linked` выполняются одним шагом фоновой задачи — отдельного шага одобрения нет. Скачать можно только версию в состоянии `linked`; любое другое состояние, включая `rejected`, отвечает как «не найдено» — существование отклонённого файла не подтверждается.

## Загрузить документ

`POST /api/v1/documents` — `multipart/form-data`: `entity_type`, `entity_id`, `title`, `file`, необязательно `doc_type`, `academic_year`, `source`, `document_id` (чтобы добавить версию существующего документа; без него — всегда новый документ, совпадение названия не объединяет). Форматы — только PDF и DOCX (уже, чем у вложений к сменам статуса), до 25 МБ. Доступна всем ролям в пределах области видимости объекта.

`202`:

```json
{"document_id": 5, "version_id": 12, "version_number": 1, "state": "quarantined", "scan_result": "pending", "job_id": 88}
```

Ответ — промежуточное состояние: файл ушёл в карантин и поставлен на антивирусную проверку фоновой задачей (`GET /api/v1/jobs/{job_id}`). Ошибки: формат не PDF/DOCX или содержимое не совпадает с расширением — `415 UNSUPPORTED_MEDIA_TYPE`; больше 25 МБ — `413 PAYLOAD_TOO_LARGE`; объект вне области видимости или не найден — `404 RECORD_NOT_FOUND`.

## Список документов

`GET /api/v1/documents?entity_type=&entity_id=` → массив документов объекта с последней версией:

```json
[{
  "id": 5, "entity_type": "university", "entity_id": 3, "title": "Договор о сотрудничестве",
  "doc_type": "", "academic_year": "", "source": "", "owner": {"id": 2, "full_name": "Павел Демо"},
  "created_at": "2026-09-16T10:00:00Z",
  "latest_version": {"id": 12, "document_id": 5, "version_number": 1, "filename": "договор.pdf", "content_type": "application/pdf", "size_bytes": 48211, "state": "linked", "scan_result": "clean", "uploaded_by": {"id": 2, "full_name": "Павел Демо"}, "created_at": "2026-09-16T10:00:00Z"}
}]
```

`GET /api/v1/documents/{id}/versions` — вся история версий (старые не удаляются и не заменяются), в том же формате `latest_version`.

## Скачивание по короткоживущей ссылке (D-160)

1. `GET /api/v1/documents/versions/{id}/download-link` → `{"url": "/api/v1/documents/versions/12/download?token=…&expires=…", "expires_at": "…"}`. Только для версии в состоянии `linked`.
2. `GET /api/v1/documents/versions/{id}/download?token=&expires=` — подписанная ссылка действует 5 минут; область видимости запрашивающего проверяется заново при скачивании, а не только при выдаче ссылки — отозванный доступ блокирует скачивание даже по ещё не истёкшей ссылке. Просроченная или подделанная ссылка — тот же `404`, что и отсутствие файла. Ответ — вложение (`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`).

## Администраторы и содержимое документов (D-158)

`crm-admin` сохраняет полный доступ в этой фазе (без ограничений, как и сейчас для остальных данных), но каждое обращение к содержимому документа администратором помечается в журнале действий отдельным полем `admin_access: true` — чтобы более поздний, отдельный этап усиления доступа (упомянутый в брифе как Phase 1) мог ограничить его без изменения модели данных.

## Хранение

Файлы лежат вне базы данных, на томе Docker `documents_data` (карантин и опубликованные файлы — разные подкаталоги; резервное копирование — как `attachments_data`, см. `docs/operations/backup.md`). Антивирусная проверка — ClamAV (`clamav` в `compose.yaml`, D-155), отказ или ошибка сканирования всегда означает `rejected`, никогда не считается «безопасно по умолчанию».
