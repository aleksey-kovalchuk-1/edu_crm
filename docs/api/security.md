# API настроек безопасности

Спецификация: `docs/superpowers/specs/2026-09-27-security-settings-design.md`; решение D-229.

Все методы требуют сеанс пользователя с ролью CRM. Методы работы с сеансами и историей возвращают **только данные текущего пользователя**. Пароли, токены, cookie и внутренние ключи сеансов не возвращаются.

## Активные сеансы

`GET /api/v1/security/sessions` возвращает список неотозванных и неистёкших сеансов пользователя. Поля каждой записи: `id` (публичный идентификатор), `device`, `ip`, `created_at`, `last_active_at`, `current`. `id` служит только для завершения сеанса; внутренний ключ cookie в ответ не попадает.

`DELETE /api/v1/security/sessions/{id}` завершает другой сеанс пользователя. Чужой или несуществующий идентификатор даёт `404`; текущий сеанс — `409` с предложением использовать «Выйти». Ответ содержит `keycloak_ended` и `message`. Сеанс CRM отзывается даже при недоступности Keycloak. Если связанный сеанс Keycloak не удалось завершить, сообщение сообщает об этом пользователю.

`POST /api/v1/security/sessions/terminate-others` завершает все остальные сеансы. Ответ: `count`, `keycloak_all_ended`, `message`. Текущее устройство остаётся в системе. Действия записываются в журнал аудита.

## История входов

`GET /api/v1/security/login-history` возвращает:

- `crm`: до 50 входов текущего пользователя за последние 30 дней (`at`, `device`, `ip`, `state`: `active`, `ended` или `expired`);
- `keycloak`: `available`, `reason`, `events`. Для событий — `at`, `type`, `label`, `ip`, `error`. События доступны с момента включения хранения событий в Keycloak. Причины недоступности: `not_configured`, `disabled`, `unavailable`; пустой `events` при `available: false` не означает отсутствия попыток входа.

В рабочем окружении хранение событий Keycloak и право чтения `view-events` включаются скриптом `scripts/keycloak-enable-login-events.sh`. Хранение настроено на 30 дней.

## Парольная политика

`GET /api/v1/security/password-policy` возвращает `available`, русскоязычный список `rules`, описание блокировки после неудачных попыток `brute_force`, `change_password_url` и `admin_console_url`. При недоступности Keycloak `available: false`, правила остаются пустыми. `admin_console_url` предоставляется только ролям `crm-admin` и `crm-superadmin`; доступ к самой консоли дополнительно проверяет Keycloak. CRM не принимает и не хранит пароль при изменении личного пароля.

Управление паролями других пользователей для суперадминистратора — отдельный API `docs/api/admin.md`.
