# API уведомлений

Спецификация: `docs/superpowers/specs/2026-09-27-notifications-design.md`; решение D-228. Все методы — только для собственных уведомлений, любая роль CRM (и `crm-superadmin`).

## Лента

- `GET /api/v1/notifications?unread=true&limit=50` — новые сверху: `{"id", "event_type", "title", "body", "link": {"type", "id", "path"} | null, "created_at", "read_at"}`. Показываются только уведомления о записях, которые пользователь видит сейчас. Исключение — «Вас сняли с ответственности за вуз» и «Вас убрали из исполнителей задачи»: они видны всегда, но `link = null`, если запись больше не видна. Договоры открываются на странице вуза (`/universities/{id}`), пункта меню «Договоры» нет.
- `GET /api/v1/notifications/unread-count` → `{"count"}` — считается по тем же правилам видимости.
- `POST /api/v1/notifications/{id}/read` → `204`; чужое или несуществующее — `404`.
- `POST /api/v1/notifications/read-all` → `204`.

## Настройки

- `GET /api/v1/notifications/preferences` → `{"groups": [{"key", "label", "events": [{"key", "label", "enabled", "default"}]}], "paused_until"}` — 4 группы, 20 событий; хранятся только изменённые пользователем флажки.
- `PUT /api/v1/notifications/preferences` — `{"preferences": {"<event_type>": true|false}}`; неизвестный тип — `422`.
- `PUT /api/v1/notifications/pause` — `{"duration": "1h" | "tomorrow" | "1w" | "forever" | "off"}` → `{"paused_until"}`. `tomorrow` — 08:00 следующего дня по часовому поясу пользователя; `forever` хранится как 9999-12-31. Пока пауза действует, уведомления не создаются и не копятся; флажки не меняются.

## Когда создаются уведомления

Таблица событий, получателей и источников — в спецификации. Уведомления создаются в той же транзакции, что и изменение (откат — без уведомлений); автор действия о своём действии не уведомляется; одно действие — одно уведомление на получателя и запись (смена статуса с комментарием и файлом — одно уведомление: «Завершили» → «Изменили этап» → «Комментарий или файл», первое включённое у получателя). Договоры, созданные импортом, не создают «Подписали договор».

## Планировщик

Сервис Compose `notifier` (`python -m app.notification_scheduler`, каждые 15 минут; `--once` — один проход). Срок сегодня, просрочка и лицензии за 30/7 дней считаются по часовому поясу каждого пользователя, не раньше 08:00 по его времени; ключ дедупликации содержит дату, поэтому повторные проходы ничего не добавляют, а перенос срока уведомляет снова. Сервис в профиле Compose `notifications` и без него не стартует: включается при выпуске явно (`docker compose --profile notifications up -d`). Предупреждения о лицензии — окном: 8–30 дней → «через 30 дней», 0–7 дней → «через 7 дней», по одному разу за срок действия.
