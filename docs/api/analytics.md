# Аналитика взаимодействий UniCRM

## Источники и правила

Оба маршрута используют один серверный снимок данных из журнала статусов «Взаимодействий» и справочника вузов. При каждом запросе сервер применяет права пользователя к вузам. Указание недоступного `university_id` возвращает 404.

Считать программу внедрённой можно только после зафиксированного перехода из этапа до «Обучение» в «Обучение». Первичное создание записи уже в «Обучении» не создаёт дату внедрения. При повторных переходах учитывается первое внедрение. Число студентов берётся из поля `Launch.students`; нулевое значение не дополняется оценкой.

Воронка за выбранный период учитывает вуз, если внутри периода записан переход на соответствующий или более поздний этап. Комментарий или файл без смены статуса переходом не считается. Вуз считается один раз на достигнутом этапе и на всех предыдущих. Названия и порядок пяти этапов берутся из `STAGE_GROUPS` процесса «Взаимодействия».

Месяц внедрения определяется в часовом поясе `time_zone`. Интерфейс берёт его из профиля пользователя; часовой пояс браузера используется только при пустом поле профиля и сопровождается пометкой. Месяцы без событий внутри периода возвращаются с `count: 0`. Рейтинг сортируется по числу внедрённых программ, затем по числу студентов. В нём не более пяти вузов.

## GET `/api/v1/analytics/interactions`

Параметры:

| Параметр | Тип | Значение |
| --- | --- | --- |
| `period_from` | `YYYY-MM-DD` | Начало периода, включительно |
| `period_to` | `YYYY-MM-DD` | Конец периода, включительно |
| `time_zone` | IANA zone | Например, `Europe/Moscow` |
| `university_id` | повторяемое целое | Один или несколько вузов; без параметра — все доступные |

Неверный период, период длиннее 120 календарных месяцев или неверный часовой пояс возвращает 422. Ответ содержит `period_from`, `period_to`, `time_zone`, `universities`, `stages` (`name`, `count`), `monthly` (`month`, `count`), `ranking` (`id`, `name`, `programs`, `students`), `has_stage_data` и `has_implementation_data`.

## GET `/api/v1/analytics/interactions.pdf`

Принимает те же параметры и права. Отдаёт PDF со всеми тремя графиками, периодом, списком выбранных вузов (или «Все вузы») и датой формирования в переданном часовом поясе. Для кириллицы встроен DejaVu Sans. Каждый блок имеет отдельную страницу; длинные периоды разбиваются на последовательные страницы месячного графика без потери месяцев. При отсутствии событий график показывает «Нет данных за выбранный период». Ответ не кешируется. Имя файла: `Аналитика_UniCRM_DD.MM.YYYY-DD.MM.YYYY.pdf`.

JSON и PDF формируются одной функцией `analytics_snapshot`, поэтому фильтры, доступ и числовые значения совпадают.

## Демонстрационный вид в интерфейсе

Если для выбранного среза все три графика пусты, экран показывает отдельно обозначенный пример с вымышленными вузами и показателями. Пример создаётся только в браузере, не отправляется в API и не включается в PDF; кнопка PDF в этом состоянии недоступна. Если реальные данные есть хотя бы для одного графика, пример не показывается и пустые графики сохраняют сообщение «Нет данных за выбранный период».

Чтобы появились реальные графики, нужно создать взаимодействие с действующим вузом, указать число студентов и зафиксировать переходы между этапами. Переход в «Обучение» создаёт дату внедрения для месячного графика и рейтинга. Ранее созданные взаимодействия с архивными демонстрационными вузами не относятся к действующим десяти вузам и не подставляются в их показатели.
