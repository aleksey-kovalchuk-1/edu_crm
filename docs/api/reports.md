# Отчёты по взаимодействиям

Все маршруты требуют входа в CRM. Сервер сначала ограничивает взаимодействия доступными пользователю вузами, затем применяет выбранные фильтры. Отсутствие выбранных вузов означает все **доступные** вузы. Передача чужого ID не расширяет область доступа.

## Методы

| Метод | Назначение |
| --- | --- |
| `GET /api/v1/reports/options` | допустимые колонки, ответственные и статусы для конструктора |
| `GET /api/v1/reports/interactions` | предпросмотр: первые 200 строк и общее число `total` |
| `GET /api/v1/reports/interactions/export` | полный скачиваемый отчёт с `format=xlsx`, `xls`, `pdf` или `json` |

Оба маршрута отчёта принимают `period_from`, `period_to` в `YYYY-MM-DD`, повторяемые `university_id`, `it_direction_id`, `it_product_id`, `owner`, `status_id` и повторяемый `column`. Если колонки не переданы, используется набор по умолчанию из `/reports/options`. Порядок `column` сохраняется. Неверный период и неизвестная колонка дают 422. Период учитывает взаимодействие, когда его срок запуска **или** смена статуса попали внутрь включительных календарных дат. Временная граница событий считается в UTC.

## Контракт JSON

`GET /api/v1/reports/interactions/export?format=json` возвращает `Content-Type: application/json`, `Content-Disposition: attachment; filename="interactions-report-YYYYMMDD.json"` и `Cache-Control: no-store`. Тело UTF-8:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `schema_version` | integer | версия схемы, сейчас `1` |
| `generated_at` | ISO 8601 string | момент формирования в UTC |
| `organization` | string | название организации в CRM |
| `filters` | object | фактически переданные значения фильтров; пустые списки означают без ограничений сверх прав пользователя |
| `columns` | array of `{key,label}` | выбранные колонки и их порядок |
| `total` | integer | число строк в `rows` |
| `rows` | array of objects | полный результат, по одному объекту на взаимодействие; ключи точно соответствуют `columns` |

Значение `students` остаётся числом; даты в строках представлены как `DD.MM.YYYY` для чтения человеком. Для машинной сортировки дат использовать исходный период в `filters`, либо явно преобразовать формат строки. Версия схемы позволяет согласовать изменение представления в будущих релизах. Пустой результат имеет `total: 0` и `rows: []`.

Экспорт сохраняет `report.export` в журнале с форматом, фильтрами, колонками и числом строк. Предпросмотр и файл строятся одним запросом и общим формирователем строк, однако файл не ограничивается 200 строками. Поле комментария может содержать персональные данные, если оно выбрано; API не удаляет их из разрешённого пользователю отчёта автоматически.

## Пример запроса

После входа в браузере можно открыть адрес:

```text
/api/v1/reports/interactions/export?format=json&period_from=2026-01-01&period_to=2026-09-30&column=university&column=program&column=students
```

Это пример параметров, а не утверждение, что в периоде есть реальные данные. Все методы и типы параметров также доступны в `/api/docs` и `/api/openapi.json`.
