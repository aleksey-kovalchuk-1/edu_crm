# API отчётов (T-050–T-054)

Модель и решения — D-180–D-183 в `docs/decisions.md`. Изменяющие запросы требуют `X-CSRF-Token`. Ошибки — `{code, message, details}`. Доступно всем ролям; область видимости — как во всём остальном API (D-141): `crm-user` получает строки только по своим вузам, даже если явно указал чужой `university_id` в фильтре.

Строка отчёта — одно взаимодействие (`Launch`). `it_direction`/`it_product`/`responsible` сопоставляются со свободным текстом `launches.product`/`launches.owner` (в этой схеме у них нет связи со справочниками ИТ-продуктов или пользователей) — см. D-180 про ограничения такого сопоставления.

## Колонки

`GET /api/v1/reports/columns` → упорядоченный список `[{"key": "university", "label": "Университет"}, …]`: `university`, `it_direction`, `it_product`, `program`, `workflow`, `status`, `responsible`, `deadline`, `last_status_change_at`.

## Сформировать отчёт (асинхронно)

`POST /api/v1/reports`:

```json
{
  "period_from": "2026-01-01", "period_to": "2026-12-31",
  "university_ids": [1, 2], "it_direction_ids": [3], "it_product_ids": [],
  "responsible": ["Иван Петров"], "status_ids": [],
  "columns": ["university", "program", "status"],
  "format": "xlsx"
}
```

Все поля фильтров необязательны и по умолчанию — пустой список (без ограничения); `columns` пустой список означает «все колонки»; `format` — один из `xlsx`, `xls`, `pdf`, `json`. `202`:

```json
{"id": 42, "status": "queued", "format": "xlsx", "created_at": "2026-09-17T10:00:00Z", "finished_at": null}
```

Запрос только ставит задачу в очередь (`background_jobs`, D-166/D-181) — сам запрос отвечает мгновенно, файл собирает `worker`. Ошибки: `period_to` раньше `period_from` или неизвестная колонка — `422 VALIDATION_ERROR`.

## Статус задачи

`GET /api/v1/jobs/{id}` — тот же общий эндпоинт, что и для импорта/документов (D-166), без отдельной схемы для отчётов: `status` — `queued`/`running`/`succeeded`/`failed`; безопасное сообщение об ошибке не раскрывает внутренние детали.

`GET /api/v1/reports` — последние 50 отчётов текущего пользователя (руководителю и администратору — все): `[{"id": 42, "status": "succeeded", "format": "xlsx", "created_at": "…", "finished_at": "…"}]`.

## Скачать готовый файл

`GET /api/v1/reports/{job_id}/download` — только автору задачи (или руководителю/администратору); чужая задача — `404`, как и несуществующая. Задача не завершена — `409 CONFLICT` («Отчёт ещё формируется»); завершилась с ошибкой — `409` («Формирование отчёта завершилось ошибкой»). Готовый ответ — вложение (`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`); путь к файлу на диске никогда не попадает в ответ API.

## Формат `json`

Задуман для будущей интеграции (устойчивые идентификаторы вместо только текста):

```json
{
  "columns": [{"key": "university", "label": "Университет"}, …],
  "rows": [{
    "id": 17, "university_id": 3, "status_id": 41,
    "university": "Северный технологический университет", "it_direction": "DevOps",
    "it_product": "Учебная среда", "program": "Python", "workflow": "Типовое взаимодействие с вузом",
    "status": "Первый контакт", "responsible": "Иван Петров", "deadline": "2026-11-15",
    "last_status_change_at": "2026-09-17T09:00:00Z"
  }]
}
```

`id`/`university_id`/`status_id` присутствуют всегда, независимо от выбранных `columns` — это устойчивые идентификаторы для последующей интеграции, а не отображаемая колонка. Ни путей файловой системы, ни секретов, ни кода подтверждения телефона, ни лишних персональных данных в ответе нет.

## Файлы `xlsx`/`xls`/`pdf`

Только выбранные колонки, только отфильтрованные строки, ничего лишнего. `xlsx` — `openpyxl`; легаси `xls` — `xlwt` (реальный OLE-файл, без LibreOffice — D-182); `pdf` — `reportlab` со встроенным кириллическим TTF-шрифтом (по умолчанию `fonts-dejavu-core`, см. Dockerfile/CI; переопределяется `REPORT_FONT_PATH` — D-183).

## Небольшой график

Отдельного эндпоинта нет: `ReportsPage` после успешного отчёта в формате `json` считает количество взаимодействий по статусам из тех же строк, что видны в скачанном файле — значения на графике не могут расходиться с отчётом, потому что это один и тот же JSON.
