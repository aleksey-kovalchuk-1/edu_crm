# API личного профиля и подтверждения телефона

Спецификация: `docs/superpowers/specs/2026-09-27-profile-and-sender-addresses-design.md`; решения D-155–D-157, D-223–D-226 в `docs/decisions.md`.

## Профиль

`GET /api/v1/profile` — профиль текущего пользователя (все роли, только своя учётная запись):
`{"id", "email", "first_name", "middle_name", "last_name", "full_name", "phone", "phone_verified_at", "timezone", "telegram", "whatsapp", "email_sender_identity_id"}`.

`PATCH /api/v1/profile` — частичное обновление; все поля необязательны:

| Поле | Правило |
| --- | --- |
| `first_name`, `last_name` | 1–100 символов; пишутся в Keycloak (`firstName`/`lastName`), `full_name = "имя фамилия"` |
| `middle_name` | 0–100 символов; пишется в Keycloak `attributes.middleName` (объявляется `scripts/keycloak-add-middle-name.sh`) |
| `timezone` | IANA-зона (`zoneinfo`) |
| `telegram` | `^[A-Za-z0-9_]{5,32}$`, ведущий `@` отбрасывается; `""` очищает |
| `whatsapp` | номер, нормализуется в `+7XXXXXXXXXX`; `""` очищает |
| `email_sender_identity_id` | id доступного адреса отправителя (см. `docs/api/email.md`); `0` — системный адрес |

Телефон через `PATCH` не меняется: любое неизвестное поле, включая `phone`, — `422`. Telegram и WhatsApp — только сохранённые контакты, интеграций с мессенджерами нет.

Ошибки: неверное поле — `422 VALIDATION_ERROR` с `details[].field`; имя совпадает с именем другого активного пользователя — `422` по `first_name`; клиент администрирования Keycloak не настроен или Keycloak недоступен при смене имени/отчества — `503 SERVICE_UNAVAILABLE`, ничего не сохраняется; недоступный адрес отправителя — `409 CONFLICT`.

Смена `full_name` (через профиль или при входе, если имя изменили в Keycloak) переписывает `launches.owner` у взаимодействий, связанных с пользователем через `owner_user_id`, и пишет событие `user.renamed`; несвязанные взаимодействия не меняются. В журнал `profile.update` попадают только названия изменённых полей.

## Запросить код

`POST /api/v1/profile/phone` — `{"phone": "+79991234567" | "89991234567" | "79991234567"}`. Принимается только российский мобильный номер (`+79…`): иначе `422` по `phone` «Укажите мобильный номер в формате +7 9XX XXX-XX-XX», SMS не отправляется.

`202` — `{"expires_in": 300}`. Код (6 цифр) отправляется по SMS; хранится только его хеш.

Ошибки: неверный формат номера — `422 VALIDATION_ERROR` (`details[].field = "phone"`); повторный запрос раньше чем через минуту — `429 RATE_LIMITED`; сбой отправки SMS — `503 SERVICE_UNAVAILABLE` (запись не создаётся, повторить можно сразу). nginx дополнительно ограничивает этот путь по адресу клиента (5 запросов в минуту — SMS стоит денег).

## Подтвердить код

`POST /api/v1/profile/phone/verify` — `{"code": "123456"}`.

`200` — `{"phone": "+79991234567", "phone_verified_at": "2026-09-16T…Z"}`.

Ошибки: нет действующего кода или он просрочен/заблокирован — `409 CONFLICT`; неверный код — `422 VALIDATION_ERROR` (`details[].field = "code"`, число оставшихся попыток не раскрывается). После 5 неверных попыток код блокируется окончательно (даже верный код после этого не подойдёт) — нужен новый запрос.

`GET /api/v1/auth/me` возвращает `user.phone`, `user.phone_verified_at`, `first_name`, `middle_name`, `last_name`, `timezone`, `telegram`, `whatsapp`. `users.phone` меняется только после верного кода.

## Хранение и приватность

Код никогда не хранится в открытом виде (только SHA-256). В журнале действий (`phone.verification_requested`, `phone.verified`) — только маскированный номер (`+7••••••••XX`), никогда полный номер или код.

## Отправка SMS

`backend/app/sms.py`: без `SMS_PROVIDER_URL` (по умолчанию в локальной разработке и CI) код пишется в лог контейнера API — аналог Mailpit для писем. Реальный шлюз подключается через `SMS_PROVIDER_URL`/`SMS_PROVIDER_API_KEY`/`SMS_SENDER` в `deploy/local/api.env` (не в репозитории). Формат запроса к `SMS_PROVIDER_URL` — предполагаемый (реальной спецификации шлюза не было в наличии) и потребует уточнения под конкретного оператора перед боевым использованием — см. docstring `app/sms.py`.
