# Выпуск публичной версии UniCRM

На рабочем компьютере приложение обслуживает `https://unicrm.tech` через Compose и публичную конфигурацию. Для повторяемого выпуска используется `scripts/deploy-public.sh`. Скрипт запускают из рабочей копии, указанной в локальном файле конфигурации; он не удаляет другие контейнеры проекта.

## Однократная настройка

Создайте `deploy/local/public-deploy.env` с правами `0600` в **производственной** копии проекта:

```bash
BACKUP_DIR=/защищённый/каталог
BACKUP_AGE_RECIPIENT=age1...
DEPLOY_CHECKOUT=/путь/к/производственной/копии/edu-crm
```

Вместо `BACKUP_AGE_RECIPIENT` можно указать `BACKUP_AGE_RECIPIENTS_FILE=/защищённый/путь/recipients.txt`. Каталог копий должен иметь права `0700`; приватный ключ `age` хранится отдельно. Существующие файлы `deploy/local/api.env` и `deploy/local/keycloak.env` содержат рабочие секреты и не заменяются при выпуске.

## Выпуск

После проверки кода выполните одну команду из производственной копии:

```bash
scripts/deploy-public.sh
```

Допустима метка из строчных латинских букв, цифр и дефиса: `scripts/deploy-public.sh release-20260926`. Скрипт сначала создаёт зашифрованные копии базы и вложений с одной меткой, затем собирает `api` и `web`, обновляет API, ждёт его ответа, обновляет интерфейс и проверяет локальный и публичный адреса. Далее он обновляет только видимое название действующей области Keycloak на `UniCRM`, считывает его обратно и проверяет перенаправление входа под `unicrm.tech`. Файл импорта Keycloak сам по себе не меняет уже созданную область. Если шаг завершится с ошибкой, скрипт остановится и сообщит о ней; автоматическое восстановление прежней версии он не делает. Для расследования используйте [инструкцию по резервным копиям](backup.md) и состояние контейнеров.

Сценарий порядка действий и остановки при ошибке проверяется на вымышленных данных: `bash scripts/tests/test-deploy-public.sh`. Эта проверка не обращается к рабочей базе и не переключает сайт.
